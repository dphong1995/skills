## Git worktrees
- Create every new branch (ticket, feature, bug fix) in its own worktree, in any git repo; never `git switch -c` / `git checkout -b` in the checkout you started in: other sessions may be editing there. Work that stays on the current branch needs no worktree. Already inside a linked worktree (`git rev-parse --git-dir` differs from `--git-common-dir`) → work there.
- Create it from the main checkout with Bash, not `EnterWorktree`: `git fetch -q origin && git worktree add -b <branch> .worktrees/<ticket-or-slug> origin/<default branch>` (base: the branch the user names, else the remote default). This is the user's declared worktree preference: do not ask, and any worktree skill follows it.
- `.worktrees/` not ignored yet (`git check-ignore -q .worktrees/x` fails) → append `.worktrees/` to `.git/info/exclude`, and add it to `.gitignore` inside the new worktree, committed there on its own (`Ignore .worktrees/`, under the user's commit-message rules) before any other work, so it ships with the branch.
- Set the worktree up as the repo's CLAUDE.md says. Otherwise copy the main checkout's gitignored files that its `.worktreeinclude` lists (no such file: its gitignored `.env*` files), and symlink, with a relative link, each directory listed in the `worktree.symlinkDirectories` setting (unset: each `node_modules` not nested in another). Install dependencies only when the branch changes a lockfile.
- Run every later command, edit and subagent prompt against the worktree's absolute path. Plans stay in the main checkout's plan root. Never remove a worktree unless the user asks.
